How to Use R-PARSE

From your first R script to understanding where every result came from.

This tutorial teaches you how to inspect your R scripts with R-PARSE. Whether you are analyzing data pipelines visually through our web interface or running automated checks from the terminal, this guide explains every command, visual graph, and dependency concept in plain English.

01 Welcome to R-PARSE

R-PARSE is a program analysis tool built in Rust for the R data science language. It helps you inspect how an R program is structured, how data columns depend on one another across pipelines, and which exact parts of a script contribute to a particular calculation.

The Core Concept: A Simple Example

Consider this simple R program:

R Source Code (example.R) 
df <- data.frame(
  price = c(10, 20),
  quantity = c(2, 3)
)

df$total <- df$price * df$quantity

Here is what happens in this code line by line:

  1. A data frame named df is created in memory.
  2. It contains two starting columns: price (values 10 and 20) and quantity (values 2 and 3).
  3. A new column called total is calculated by multiplying df$price by df$quantity.
  4. In ordinary R execution, the resulting values are 20 (10 × 2) and 60 (20 × 3).
  5. R-PARSE investigates the relationship: It mathematically proves that total was derived specifically from price and quantity.
💡 Running Code vs. Static Analysis

Running an R script executes the code line-by-line using an R interpreter (like GNU R or RStudio) to calculate concrete numbers (like 20 and 60).
Static program analysis inspects the program's grammatical structure, variables, and dataflow without running the code. It determines why and where columns connect, making it 100% offline, deterministic, and safe for analyzing untrusted or unfamiliar scripts.

When is R-PARSE Useful?

  • Auditing Unfamiliar Code: Understand complex 500-line scripts written by colleagues or predecessor researchers.
  • Tracking Data Provenance: Discover exactly which source columns and calculations created an output metric.
  • Program Slicing: Strip away hundreds of lines of unrelated code to isolate only the statements that affect a suspicious number.
  • Pipeline Debugging: Verify how data frames evolve step-by-step through filtering, mutation, and selection verbs.

03 Method A — Using the Visual Studio

Follow these numbered steps to start the R-PARSE Studio on your computer and begin analyzing code.

1

Understand What You Need (Prerequisites)

R-PARSE runs completely locally on your computer. Your code is never uploaded to any cloud service. Here is what you need:

  • The R-PARSE Repository: A downloaded or cloned copy of the R-PARSE folder.
  • Rust & Cargo: The Rust compiler toolchain (version 1.70 or newer). Verify by typing cargo --version in your terminal.
  • A Modern Web Browser: Google Chrome, Mozilla Firefox, Microsoft Edge, or Safari.
  • GNU R (Optional): Only required if you explicitly run dynamic execution mode. Pure static analysis requires zero R installations.
2

Open Your Terminal in the Project Directory

A terminal (PowerShell on Windows, Terminal on macOS/Linux) is a text window where you type commands. Open your terminal and change into the implementation subfolder of R-PARSE:

PowerShell / Terminal 
cd implementation

Navigate to the implementation directory of the cloned repository:

Terminal 
cd implementation
3

Start the Local Studio Server

Run the following command to compile and launch the local R-PARSE Studio server:

PowerShell 
cargo run -p rparse-cli -- studio fixtures/showcase_pipeline.R --port 8080 --open

Here is what each piece of this command does:

  • cargo run: Compiles and executes the Rust project.
  • -p rparse-cli: Selects the command-line interface package in the workspace.
  • --: Separates Cargo flags from R-PARSE arguments.
  • studio: Subcommand that starts the local HTTP analysis daemon.
  • fixtures/showcase_pipeline.R: Preloads a sample R script.
  • --port 8080: Tells the server to listen on local port 8080.
  • --open: Automatically launches your default web browser to the application.
⚠️ Keep this terminal window open!

The Studio web interface communicates with the background server running in this terminal. If you close this terminal window or press Ctrl+C, the local server will shut down and the web page will show "Offline".

4

Open the Studio in Your Browser

If your browser did not automatically open, open Google Chrome, Firefox, or Edge and navigate to:

URL Address 
http://localhost:8080/studio

You will see the R-PARSE Studio header, the source code buffer on the left, and the five analysis graph views on the right. Visit http://localhost:8080/ at any time to return to the interactive landing page.

5

Load or Edit an R Script

You have three ways to load code into R-PARSE Studio:

  • Preset Examples: Click New Analysis in the top header to return to the entry card, then choose an example from the dropdown (such as Showcase Pipeline or Uncertainty Handling).
  • Load a File: Click the Load File... button to open any .R file on your computer.
  • Edit Code in Place: In the workspace, click the Edit button in the source pane toolbar. You can type or paste custom R code directly into the editor!
6

Analyze the Program

Click the orange ▶ Analyze Program button (or press Ctrl + Enter in the editor).

Within milliseconds, the Tier 1 deterministic Rust core parses the code, builds the AST, computes variable scopes, determines dataflow transfer functions, constructs the Program Dependence Graph, and updates all five visual tabs.

⚠️ Stale Results Indicator

If you edit source code in the editor, R-PARSE immediately displays an amber "Source code has been modified" banner. This prevents you from mistaking old graph results for newly typed code. Click Reanalyze to update or Revert to restore the original code.

7

Explore Output Across the Five Views

Use the tab strip in the header to switch between the five analytical dimensions:

  1. Column Provenance: See how columns flow into verbs and produce new column versions.
  2. Unified PDG: Inspect statement-to-statement dataflow and control dependencies.
  3. Backward Slice: Choose an output column to highlight all contributing source statements.
  4. Schema Evolution: Track dataframe column additions, removals, and modifications step-by-step.
  5. AST Explorer: Inspect the concrete syntax tree (CST) and normalized semantic IR.

See Section 4 below for a comprehensive guide to interpreting each of these five views!

8

Shut Down Safely When Finished

When you are finished using R-PARSE Studio:

  • Close your browser tab.
  • Switch back to your terminal window and press Ctrl + C on your keyboard.
  • The terminal will print Studio server stopped. and return to your standard prompt.

04 Understanding the Five Analysis Views

R-PARSE breaks program analysis down into five specialized visual perspectives. Here is how to understand and interpret each one:

VIEW A

Column Provenance Explorer

Lineage & Derivations
What is it? A directed derivation graph tracking columns through pipeline operations.
What it answers: "Which exact source columns and arithmetic expressions created output column X?"
What to look at: Orange pills represent Column Versions (e.g. df$price); green rounded boxes represent Derivation Verbs (e.g. mutate). Arrows point from inputs into derivations, and derivations point to output column versions.
Interaction: Click any node to open the Contextual Inspector on the right. You can see its upstream dependencies, downstream consumers, and click "Jump to Source" to highlight the exact code line!
Limitations: Static analysis proves column dependencies, not concrete row numbers. Joins (like left_join) are not modeled statically.
VIEW B

Unified Program Dependence Graph (PDG)

Operation Structure
What is it? A graph representing all control and data dependencies across every statement and variable in your script.
What it answers: "How do statements communicate values, and which conditions control whether a statement runs?"
Dependency Types: • Data Dependency (Blue arrows): A value produced by statement A is used as an input to statement B.
• Control Dependency (Purple dashed arrows): Whether statement B runs depends on an if condition in statement A.
• Row Selection Dependency (Violet arrows): A dataframe filter condition (e.g. price > 0) controls which rows flow into downstream operations.
• Unknown Dependency (Red dashed arrows): Marks dynamic indexing or unmodeled calls.
Toolbar Filters: Use the checkboxes in the PDG toolbar to toggle Data, Control, RowSelection, and Unknown edges on and off to unclutter complex graphs.
VIEW C

Backward Program Slice Inspector

Code Isolation
What is it? A sub-program analysis technique that extracts only the statements and sub-expressions relevant to a specific slicing target.
What it answers: "If I only care about calculating df2$total, which lines of code can I safely ignore?"
Retention States: • [FULL] (Fully Retained): The entire statement directly influences the target.
• [PARTIAL] (Partially Retained): Some parts of the line are needed ([KEEP]) while unrelated calculations on the same line are discarded ([DROP]). For example, in mutate(df, total = price * qty, tax = age * 0.1), total is kept while tax is dropped!
• [NONE] (Not Retained): Unrelated or downstream code that has zero effect on the target.
Crucial Note: R-PARSE annotates and highlights your source code lines. It does not rewrite or output a new synthetic R script file.
VIEW D

Dataframe Schema Evolution

Step-by-Step Schemas
What is it? A timeline showing how a data frame's column schema changes across sequential pipeline steps.
What it answers: "Which columns were added, dropped, or modified by each dplyr verb?"
Legend Indicators: • +added: New column created at this step.
• -removed: Column dropped (e.g. by select(-col)).
• ~modified: Column overwritten with new values.
• =retained: Column passed through unchanged from the previous version.
VIEW E

AST & CST Syntax Explorer

Compiler Grammar
What is it? An interactive hierarchical tree showing how the parser breaks your R text into grammatical syntax nodes.
Two Representations: • Concrete Syntax Tree (CST): Tree-sitter grammar nodes, preserving exact source tokens, operators, commas, and syntax recovery nodes.
• Semantic IR / AST: Normalized semantic intermediate representation used by R-PARSE for scope analysis and dataflow equations.
Features: Search box with live match counter, Expand All / Collapse All buttons, and clicking any node automatically selects its exact line and byte range in the source editor!

05 Method B — Using the Command Line

The R-PARSE command line interface (CLI) is perfect for developers who prefer working in a terminal or want to automate analysis in CI/CD scripts.

Terminal Fundamentals (For Absolute Beginners)

If you have never used a command line before, here are the key concepts:

  • Terminal: An application (like Windows PowerShell or Command Prompt) that executes text commands.
  • Command: The program to run (e.g. rparse or cargo run).
  • Argument: Information you give to the command, like the path to your file (fixtures/showcase_pipeline.R).
  • Flag / Option: Modifiers prefixed with dashes, like --format json or --help.
  • Current Directory: The folder your terminal is currently looking at. Check it by typing pwd or Get-Location.

Step 1: Check Environment & Print Help

In your terminal, navigate to the implementation folder and verify R-PARSE:

PowerShell 
cargo run -p rparse-cli -- --help

You will see the top-level help menu listing the primary commands: analyze, provenance, slice, and studio.

Step 2: Command 1 — Analyze a Script (analyze)

The analyze command runs the complete parsing and semantic analysis pipeline, reporting statement counts, dataframe states, and graph topology:

PowerShell 
cargo run -p rparse-cli -- analyze fixtures/showcase_pipeline.R

To get machine-readable JSON:

PowerShell 
cargo run -p rparse-cli -- analyze fixtures/showcase_pipeline.R --format json

To generate a standalone interactive HTML report file:

PowerShell 
cargo run -p rparse-cli -- analyze fixtures/showcase_pipeline.R --format html --output report.html

Step 3: Command 2 — Trace Column Provenance (provenance)

The provenance command isolates how an individual dataframe column was derived. The target column is specified using the --column flag with dataframe$column syntax:

PowerShell 
cargo run -p rparse-cli -- provenance fixtures/showcase_pipeline.R --column 'df2$total'

Note: In PowerShell, surround arguments containing the $ sign in single quotes (e.g. 'df2$total') so PowerShell does not interpret $total as an empty shell variable!

Step 4: Command 3 — Compute a Backward Slice (slice)

The slice command takes a criterion and computes a backward slice, marking which statements and sub-expressions must be kept or dropped:

PowerShell 
cargo run -p rparse-cli -- slice fixtures/showcase_pipeline.R --criterion 'df2$total'

Step 5: Useful Options & Flags

Option Flag Accepted Values Description
--format text, json, dot, html Controls output representation. Defaults to human-readable text. Use json for automated pipelines.
-o, --output <FILE_PATH> Writes output directly to a file on disk instead of printing to the terminal stdout.
--graph pdg, provenance, cfg Used with analyze to export graph topologies into Graphviz DOT or JSON format.
--mode static, assisted, execute Analysis mode. Defaults to static (pure offline Rust). execute requires an installed GNU R interpreter.
--seed df=col1,col2 Explicitly seeds the starting schema of an external or dynamically loaded dataframe.

06 Understanding CLI Output

Let's examine actual terminal output produced by R-PARSE and see how each section is interpreted.

Reading rparse provenance Output

Actual Terminal Output 
R-PARSE COLUMN PROVENANCE
─────────────────────────
Target Column:     df2$total (v2)
Certainty State:   KNOWN_STATIC

Direct Input Columns:
  ← df$price (v0)
  ← df$quantity (v0)

Transitive Source Columns:
  ← df$price (v0)
  ← df$quantity (v0)

Derivation Chain:
  [Mutate] df$price, df$quantity → df2$total

What this tells you:

  • Target Column: df2$total (v2) means this is column total on dataframe df2 at version 2 of the pipeline.
  • Certainty State: KNOWN_STATIC proves the relationship was deterministically verified by compiler analysis. If dynamic code like eval() was involved, it would display UNKNOWN_STATIC.
  • Direct Input Columns: Lists the immediate inputs to the multiplication (df$price and df$quantity).
  • Derivation Chain: Confirms that a mutate verb combined the price and quantity inputs to produce total.

Reading rparse slice Output

Actual Terminal Output 
R-PARSE BACKWARD STATIC SLICE
─────────────────────────────
Criterion:         df2$total
Confidence:        COMPLETE
Contains Unknowns: NO

Slice Metrics:
  Retained Semantic Elements:  19
  Fully Retained Statements:    1
  Partially Retained Statements:2

Retained Program Statements:
  [PARTIAL] Line 25:  df <- data.frame(price = 100, quantity = 2, age = 30)
    [KEEP] price = 100
    [KEEP] quantity = 2
    [DROP] age = 30
  [FULL] Line 26:  filtered <- filter(df, price > 0)
  [PARTIAL] Line 27:  df2 <- mutate(filtered, total = price * quantity, discount = age * 0.05)
    [KEEP] total = price * quantity
    [DROP] discount = age * 0.05
  [NONE] Line 28:  df3 <- mutate(df2, tax = total * 0.18)

What this tells you:

  • Sub-statement Attribution: Notice how Line 25 and Line 27 are marked [PARTIAL]. R-PARSE knows that price and quantity matter ([KEEP]), but age = 30 and discount = age * 0.05 have zero effect on total ([DROP])!
  • Control Dependency on Filter: Notice that Line 26 (filter(df, price > 0)) is marked [FULL]. Even though it does not assign a new column value, filtering rows determines which data points flow into total!
  • Downstream Exclusion: Line 28 (df3 <- mutate(df2, tax = total * 0.18)) is marked [NONE] because downstream consumers cannot retroactively change earlier values.

07 A Complete End-to-End Example

Let's walk through an entire analysis from creating an R script to interpreting every view.

Step 1: Save the R Script

Create a file named pipeline.R with the following content:

R (pipeline.R) 
df <- data.frame(price = 100, quantity = 2, age = 30)
filtered <- filter(df, price > 0)
df2 <- mutate(filtered, total = price * quantity, discount = age * 0.05)
df3 <- mutate(df2, tax = total * 0.18)

Step 2: Trace Provenance for df2$total

In your terminal, run:

PowerShell 
cargo run -p rparse-cli -- provenance pipeline.R --column 'df2$total'

The output proves that df2$total originates from df$price and df$quantity, and is uninfluenced by age.

Step 3: Slice for df2$total

PowerShell 
cargo run -p rparse-cli -- slice pipeline.R --criterion 'df2$total'

What You Learned

🎓 Key Takeaways
  • Lineage: total depends on price and quantity.
  • Independence: discount = age * 0.05 is independent and safely dropped.
  • Row Control: Row filters like price > 0 create row selection dependencies that are preserved.
  • Downstream Safety: Later operations (like tax = total * 0.18) are excluded because they do not influence total.

08 Common Errors & Solutions

Encountering an issue? Look up your situation in this troubleshooting guide:

Symptom or Error Likely Cause Recommended Solution
Browser says "Unable to connect" or "Connection Refused" The local Studio server is not running or the terminal was closed. Make sure your terminal is still running cargo run -p rparse-cli -- studio .... Check that you are navigating to http://127.0.0.1:8080/.
"Address already in use" (Error: Port 8080 occupied) Another application (or a previous R-PARSE session) is already listening on port 8080. Choose a different port with the --port flag, e.g. --port 8085, and open http://127.0.0.1:8085/.
"cargo: command not found" or "not recognized" The Rust toolchain is not installed or not in your system PATH environment variable. Install Rust from rustup.rs. Restart your terminal after installation.
"Resolution error: Column 'X' not found in dataframe 'Y'" The column name in your --column or --criterion argument does not match any known column. Run rparse analyze script.R first to inspect discovered dataframe schemas and exact column names.
In PowerShell, argument gives empty string or error PowerShell treats unquoted $total as a shell variable and replaces it with nothing. Always wrap criteria in single quotes: 'df2$total', or escape with backtick: df2`$total.
Results do not match edited code in Studio The code was modified in the editor without triggering reanalysis. Click the orange Reanalyze button in the stale warning banner or press Ctrl+Enter.
Output shows UNKNOWN_STATIC or missing edges The script contains dynamic operations (like eval(), get(), or unmodeled joins). R-PARSE explicitly models uncertainty rather than inventing false dependencies. See Section 9 below.
"GNU R executable not found" in execute mode The --mode execute flag was passed, but R is not installed or not on PATH. Static analysis mode (--mode static, the default) requires zero R installations. Only use execute if GNU R is installed.

09 What R-PARSE Can and Cannot Do

Scientific honesty is a foundational value of R-PARSE. We clearly communicate the boundaries of our static analysis engine:

What R-PARSE Does (Capabilities):

  • Deterministic Static Analysis: 100% offline analysis of R code, scopes, and column pipelines.
  • Column-Aware Provenance: Traces derivations across verbs like mutate, select, rename, and filter.
  • Sub-Statement Slicing: Annotates precisely which expressions within a line are retained or dropped.
  • Explicit Uncertainty: Marks unresolvable expressions as UNKNOWN_STATIC rather than guessing or silently omitting them.

What R-PARSE Does Not Do (Limitations):

  • It Does Not Execute R in Static Mode: Static analysis examines code structure. It does not compute concrete row values (e.g. it knows total = price * qty, but does not calculate that 10 × 2 = 20 unless runtime mode is used).
  • It Does Not Rewrite Your Code: Backward slicing annotates and highlights source regions. It does not output a rewritten, synthesized R script.
  • Joins are Currently Unmodeled: Verb joins such as left_join and inner_join are not modeled in the current Tier 1 engine.
  • Dynamic Metaprogramming Cannot Be Statically Proven: Dynamic R features such as eval(parse(text = ...)) cannot be known before execution and are marked UNKNOWN_STATIC.
  • Local Server: The Studio runs on your local machine; there is no cloud deployment or remote hosting.

10 Frequently Asked Questions

Do I need to know the Rust programming language to use R-PARSE?
No! R-PARSE is written in Rust for speed, safety, and determinism, but as a user you only interact with R code, the visual website, or standard terminal commands.
Do I need GNU R installed on my computer?
No, not for static analysis or the Visual Studio! Pure static analysis runs 100% offline inside the compiled Rust engine. GNU R is only required if you explicitly request dynamic runtime execution with the --mode execute flag.
Does R-PARSE execute my script when I analyze it?
No. In default static mode, R-PARSE parses the text into an Abstract Syntax Tree (AST) and evaluates mathematical dataflow transfer functions. Zero user code is executed, making it completely safe to analyze untrusted R code.
Can I analyze my own custom .R script?
Yes! In the Visual Studio, click Load File... or paste your code into the in-place editor. In the CLI, simply pass the path to your script: rparse analyze path/to/my_script.R.
What is the difference between column provenance and a backward slice?
Column Provenance shows the lineage tree of columns ($C_{in} \to C_{out}$).
Backward Slicing highlights the actual lines and sub-expressions in your source code that contributed to calculating a target criterion.
What does an UNKNOWN_STATIC result mean?
It indicates that a line of code uses dynamic R features (such as eval(), runtime indexing, or unmodeled calls) whose behavior cannot be mathematically proven without running R. R-PARSE marks this uncertainty explicitly so you know where human inspection is required.
Can I automate analysis using JSON output in GitHub Actions?
Yes! Pass --format json to any command. R-PARSE outputs structured JSON containing statements, diagnostics, PDG nodes, and slice retention metadata, perfect for automated code quality gates.
