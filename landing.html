04 / PROGRAM SLICING

The case file is long. The evidence is short.

Most of what a script says is not about the thing you're asking about.

Backward slicing doesn't rewrite your program or hand you a smaller one. It does something more honest. It leaves your code exactly as written and marks the regions that matter to your question.

The rest is not deleted. It's just not evidence.

05 / THE STUDIO ARCHITECTURE

Five exhibits. One source.

The R-PARSE Studio keeps your code at the center and lays out the evidence around it.

Exhibit 01 — Column Provenance

Where a column came from, edge by edge.

Traces fine-grained derivation chains ($C_{in} \to C_{out}$) across base assignments, mutate verbs, and mathematical expressions, tracking precise column version lifecycles.

Exhibit 02 — Program Dependency Graph

Which statements depend on which.

A unified program graph distinguishing variable data dependencies, CFG branch control dependencies, dataframe row-selection dependencies, and explicit uncertainty boundaries.

Exhibit 03 — Backward Slice

Pick a target; see the source regions that bear on it.

Computes character-accurate backward slices with sub-statement attributions ([KEEP] vs [DROP]), illuminating the precise semantic elements that contribute to the target.

[DROP] title <- "Q3 report"
[KEEP] df$total <- df$price * df$quantity

06 / BOUNDARIES & CERTAINTY

What the analysis can't see, it says so.

R is dynamic. Code that builds column names at runtime, or modifies programs as they run, can exceed what static analysis can establish. Joins like left_join and inner_join are not modeled today.

When R-PARSE can't establish something, the result may come back as unknown. An investigator who marks a gap is more useful than one who invents an answer.

• No dynamic metaprogramming fabrication (eval, substitute)
• Joins not modeled in frozen research scope
• Explicit uncertainty (UNKNOWN_STATIC) preserved
• Tier 1 static analysis never executes GNU R
